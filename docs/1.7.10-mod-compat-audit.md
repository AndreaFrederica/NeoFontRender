## 二、主要 1.7.10 适配决策

### 核心（src/main）
- `2c9bbc3`：`AdvancedTextApi`/`FontRenderSpec`/`EnchantmentTextRenderer`/`ScopedFontRenderBypass` 直接移植；`FontManager.getScopedTextBackend`、`CosmicTextRenderer`/`AwtModernTextRenderer` 作用域构造器按 1.7.10 现有结构合入；`MixinGuiEnchantment` 目标类 1.7.10 同名同签名，直接注册。捆绑 `sric_minecraft_words.ttf`（Apache-2.0，附 LICENSE 文件）。
- `7fd466d` 核心部分：`CjkLineBreakRules`、`FontRenderTuning` 投影重构、`AwtTtfGlyphProvider.canDisplay(int)`、`FontSet` 多 provider layout、`MixinFontRenderer` CJK 换行钩子、`fix.cjkLineBreak` 配置（默认开启）全部移植；`FontManager` 增加 Java SansSerif 复合字体的最终系统回退。
- 设置界面（附魔字体后端/字体列表、CJK 换行开关）按 1.7.10 现有 ModularUI 控件体系合入。

### UIE（addons/ui-enhancements）
- **language**：语言列表搜索/收藏。1.7.10 `GuiLanguage$List` 为包私有内部类，部分访问走反射；`GuiSlot` 无 `handleMouseInput`，收藏星区点击改在 `drawScreen` HEAD 注入处理；语言切换重载目标改为 1.7.10 的 `Minecraft.refreshResources()`。
- **ResourceReload**：进度条/脉冲/设置页移植。1.7.10 `refreshResources()` 不 push ProgressManager bar，进度粒度较 main 粗（0.02→0.94→0.97→1.0），由 TextureManager 脉冲驱动帧动画，属版本差异。
- **mainmenu / worldcreation**：继续上次游戏、创建世界现代布局。修正了 main 把 `ClientTickEvent` 订阅者注册到 Forge 总线的问题（1.7.10 侧注册到 FML 总线）；`GuiCreateWorld` 全套 SRG 字段名适配。
- **zoom**：1.7.10 无 `EntityViewRenderEvent.FOVModifier`，改为 `EntityRenderer.getFOVModifier` RETURN 注入修改 FOV；鼠标灵敏度 Redirect 与 main 一致。

- **tabbychat**：main 的 `vendor/tabbychat-upstream`（mnm.mods 原包名）改动映射到 1.7.10 的 `vendor/tabbychat-private`（`neofontrender.addons.vendor.tabbychat`）：`ChatArea`（选择复制/头像/图标/渐隐接入）、`TextBox`（拖选/右键菜单）、`ChatTextUtils`（物品图标装饰与 sender 解析）、`ChatMessage`（senderName 懒解析、首 fragment 标记）、`MixinGuiChat`（Salutation 输入几何上报、聊天快捷键接管）；发送者身份按 1.7.10 现实从 UUID 改为 String 账号名。三个跨任务对接点已落实：`ChatArea.markDirty()` 供 `ChatRuntimeController.refreshLayout()` 调用链；`ExternalChatCompat.updateSalutationInput/removeSalutationInput` 上报；`ChatHeadRenderer/ChatItemIconRenderer.renderVanilla` 经 `MixinGuiNewChatSmoothScroll` 接入 vanilla 聊天渲染。

## 四、NightConfig relocate（d55442f）评估结论：不移植

- main 的动机：Cleanroom 的 jar-module 系统拒绝重复模块，且 1.12.2 的 LibraryEx/Reagenchant 内嵌 night-config 3.6.0 上游包名。**1.7.10 无 Cleanroom 模块系统**（LaunchClassLoader 扁平加载），冲突机制不存在。
- GTNH 生态 1.7.10 mod 极少内嵌 night-config（GTNHLib 使用自有配置体系），实际冲突概率低。
- 1.7.10 构建为 GTNH convention + RetroFuturaGradle；启用其 shadow 模块（`usesShadowedDependencies` + auto-relocation）会改变 jar 产物结构与 reobf/发布流程，改动风险高于防御收益。
- 若日后 1.7.10 环境出现真实的 night-config 类冲突，再按 GTNH shadow 标准路径（`shadeCompile` + `shadowJar relocate`）处理。

- zoom 的事件总线修正、chat 的帧/刻轮询机制与 main 存在有意偏差，建议进游戏实测：CJK 换行、语言搜索/收藏、资源重载进度、主菜单继续游戏、创建世界布局、zoom、悬停动画、聊天头像/图标/选择复制、Salutation 补全面板。

- ResourceReload 进度粒度较 main 粗（1.7.10 无选择性资源重载 API）。

## 六、后续修复记录

- **2026-07-30 按 T 打开聊天崩溃**（`IllegalStateException: TabbyChat has not been started by its host`）：1.7.10 的 vendored TabbyChat 从未启动（`TabbyChat.start(host)` 无调用点，main 的 `EnhancedChatModule.preInit` 初始化在移植时遗漏），而 `MixinGuiChat` 在 `GuiChat` 构造阶段就解析 `TabbyChat.getInstance()`。修复：`EnhancedChatModule.preInit` 补启动装配（外部 TabbyChat mod 存在时跳过）与 `ChatStyleConfig.load()`，`init` 补 TabbedChat/ChatStyle 设置页注册；`TabbyChat` 加 `isStarted()` 幂等保护；`MixinGuiChat` 的 `tc` 改门控内懒获取，各注入点补 `tabbedChatEnabled()` 门控（对齐 main），`onDrawScreen` 在 tabbed 禁用时恢复原版输入框背景绘制（原无条件 noop 会丢背景）。已通过 `:addons:ui-enhancements:compileJava` 验证。
- **2026-07-30 启动崩溃**（`NoClassDefFoundError: com/swabunga/spell/event/WordTokenizer`）：TabbyChat 启动后 `Spellcheck` 触发 Jazzy 类加载，但 Jazzy 以 ContainedDeps 嵌套 jar 打包，1.7.10 dev 启动路径不处理嵌套 jar（类字节为 null）。修复：UIE `build.gradle` 的 jar 任务改为平铺解包 `contain` 依赖（`zipTree`，与根项目 `addon.gradle` 一致），manifest 移除 `ContainedDeps`/`NonModDeps`。
- **2026-07-30 按 T 空遮罩 + 点击崩溃**（`GuiTextField.field_146211_a` 为 null 的 NPE）：`TabbyChat.start` 放在 preInit，此时 `Minecraft.fontRenderer` 尚未创建（1.7.10 在 `beginMinecraftLoading` 后第 530 行才初始化），导致 TabbyChat 的 `GuiText` 输入框以 null fontRenderer 构造。修复：启动移至 `init()`（`finishMinecraftLoading` 在 fontRenderer 创建之后触发）。
- **2026-07-30 列表滚动条无法拖动**：`MixinGuiSlotSmoothScroll` 的缓动注入点在 vanilla 拖动轮询**之后**，每帧把 `amountScrolled` 覆盖回 scroller 旧值，vanilla 拖动位移被吞（vanilla 列表全失效；Forge 列表因注入在 HEAD 得以幸免）。修复：两个滚动 mixin（`MixinGuiSlotSmoothScroll`、`MixinForgeGuiScrollingListSmoothScroll`）在鼠标驱动期间（左键按下且 `initialClickY != -1.0F`）直接 `sync` 跟随 vanilla，跳过缓动。
- **2026-07-30 聊天框完全不渲染**（输入/发送功能正常）：`PlayerLoginHandler` 订阅的 `FMLNetworkEvent` 发布在 **FML 总线**，而 `MinecraftTabbyChatHost.registerEventHandler` 只注册到 **Forge 总线**——`onJoin` 从未触发、`hookIntoChat()` 从未执行，TabbyChat 的 `GuiNewChatTC` 从未装入 HUD（日志无 "Successfully hooked into chat."）。修复：`registerEventHandler` 改为双总线注册（`MinecraftForge.EVENT_BUS` + `FMLCommonHandler` bus；两类事件各走一条总线，无重复投递风险）。
- **2026-07-30 聊天无法输入/发送**（时间相关：GC 后必现）：lwjgl3ify 的 `MixinGuiTextField` 把 `textboxKeyTyped` 的 `writeText` 重定向为写入 `TextFieldHandler.textBuffer`（SDL 文本事件队列），而 `textBuffer` 只在 `TextFieldHandler.focusedTextInput` 非空时填充。TabbyChat 在 `onInitGui` 把 `GuiChat.inputField` 替换为长期持有的 dummy 输入框后，lwjgl3ify 注册的焦点框仍是 vanilla initGui 创建的短命实例——`focusedTextInput` 是 `WeakReference`，GC 回收后文本事件永久停喂，`writeText("")` 静默丢弃全部输入。修复：`onInitGui` 替换输入框后补一次 `inputField.setFocused(true)`，把长寿命的 dummy 重新注册为 lwjgl3ify 的 IME 焦点框。1.12.2 Cleanroom 虽用 LWJGL3 但无 SDL 文本事件机制，不受影响；1.7.10 + lwjgl3ify 环境对任何"替换 GuiChat.inputField 为长寿对象"的 mod 都需注意此陷阱。诊断过程（运行时探针）已确认：`textboxKeyTyped` 被正常调用、`focused/enabled` 均正常、`textBuffer` 为空导致写入无效。
